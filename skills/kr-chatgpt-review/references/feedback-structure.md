# 피드백 구조 (feedback structure)

ChatGPT 검토는 두 단계다. **ChatGPT가 공격하고, 에이전트가 판정한다.**
ChatGPT 답변은 검토 의견일 뿐 출처가 아니다.

## 1. ChatGPT에게 요구하는 형식

`chatgpt-review.js build-prompt`가 이 형식을 프롬프트에 박아 넣는다. 형식을 바꾸려면
스크립트의 `buildPrompt()`와 `FEEDBACK_SECTIONS`를 같이 고친다.

| 섹션 | 무엇을 받는가 | 왜 필요한가 |
|---|---|---|
| 0. 한 줄 판정 | 지지 / 부분 지지 / 지지 안 함 + 이유 | 결론 수준의 경고등 |
| 1. 논리 비약 | 원문 주장 · 왜 약한가 · 무엇이 있으면 성립하나 · 심각도 | 가장 중요한 산출물 |
| 2. 숫자·계산 점검 | 원문 수치 · 문제 · 다시 계산할 것 | 계산 오류는 메모 가치를 0으로 만든다 |
| 3. 빠진 반대 논리 | 반대 논리 — 결론에 미치는 영향 | 확증 편향 점검 |
| 4. 확신도 점검 | 원문 표현 · 과장/과소 · 제안 표현 | 추론 강도 조정 |
| 5. 결론을 뒤집을 데이터 | 관측 가능한 데이터 + 확인 시점 | Decision-Changing Issues 보강 |
| 6. 먼저 고칠 3가지 | 우선순위 1~3 | 반영 순서 |

프롬프트 규칙: 칭찬·요약 금지, 원문 인용, 새 사실은 URL 또는 "확인 필요",
계산은 직접 재계산, 기준일 이후 정보는 표시, 지적할 게 없으면 "없음".

`chatgpt-feedback.json`의 `missingSections`가 비어 있지 않으면 형식이 깨진 답변이다.
누락 섹션만 같은 대화에서 다시 요청하거나, 누락 사실을 판정표에 적는다.

## 2. 에이전트 판정 — `chatgpt-triage.md`

피드백을 받으면 지적 하나하나를 판정해서 메모 옆에 `chatgpt-triage.md`로 쓴다.

```markdown
# ChatGPT 검토 판정

- 메모: analysis-example/kr/<company>/memo.md
- 피드백: chatgpt-feedback.md (대화 URL)
- 판정: <ChatGPT 한 줄 판정> → 에이전트 결론: <유지 / 수정 / 결론 변경>

| # | 섹션 | 지적 요약 | 판정 | 근거 | 메모 반영 |
|---|---|---|---|---|---|
| 1 | 논리 비약 | ... | 수용 | 반기보고서 p.xx 재확인 | 「화물」 2번째 문단 수정 |
| 2 | 숫자 | ... | 기각 | 원문 계산 (138-124)×19,762 재검산 결과 맞음 | — |
| 3 | 반대 논리 | ... | 확인 필요 | 1차 자료 없음 | Decision-Changing Issues에 추가 |

## 반영하지 않은 것
- 기각·확인 필요 항목과 이유 한 줄씩
```

판정은 네 가지뿐이다.

| 판정 | 조건 | 메모 처리 |
|---|---|---|
| 수용 | 지적이 맞고 근거를 1차 자료나 재계산으로 확인했다 | 메모 수정 |
| 부분 수용 | 방향은 맞지만 범위·강도가 과하다 | 표현·확신도만 조정 |
| 기각 | 원문이 맞다는 근거가 있다 | 수정 없음, 이유 기록 |
| 확인 필요 | 맞을 수 있지만 지금 확인할 1차 자료가 없다 | 결론에 안 넣고 Decision-Changing Issues 또는 후속 확인 목록으로 |

## 3. 반영 규칙

1. **ChatGPT가 준 숫자·사실을 그대로 메모에 넣지 않는다.** DART·IR·리포트 원문으로 다시
   확인한 값만 넣고, 출처는 ChatGPT가 아니라 그 1차 자료로 적는다.
2. **메모의 결론은 에이전트가 판단한다.** ChatGPT 판정이 "지지 안 함"이어도 판정표에서
   수용된 지적이 결론을 뒤집을 만큼일 때만 Structured Stance를 바꾼다.
3. **수정은 원본 `memo.md`에 한다.** 그 뒤 `kr-my-voice`(말투), `kr-naver-blog-publish`
   변환을 다시 돌린다. 이미 임시저장한 초안은 준비 단계를 다시 실행해야 바뀐다.
4. **검토는 최대 2회.** 2회차는 1회차에서 수용한 수정이 새 비약을 만들지 않았는지만 본다.
   같은 지적이 되풀이되면 판정표의 기존 판정을 유지한다.
5. **판정표와 피드백 원문은 메모 본문에 붙이지 않는다.** 블로그 변환·품질 게이트가 모르는
   섹션이 생기기 때문이다. 메모에는 반영 결과만 남는다.
